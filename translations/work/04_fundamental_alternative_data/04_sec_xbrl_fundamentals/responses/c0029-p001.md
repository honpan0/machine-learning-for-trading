1. SEC 的 XBRL Frames API 足以在無須訂閱供應商的情況下，組成橫斷面基本面面板。代價是面板採 SEC 而非供應商的規格：曆年季度、us-gaap 概念名稱，以及依申報形式每項事實資料一列。
2. 概念缺漏通常是標籤差異，而非未揭露。若申報者以 ASC 606 後的概念標記營收首列，`revenues` 就會是空值，因此在將空值視為缺口前，應逐概念衡量涵蓋程度，並在任何插補前先解讀空值模式。
3. Frames 來源的面板無法確保歷史時點安全性，衡量結果證明了這點：此處沒有任何一列的日期落在法定申報期限內，因為 Frames 傳回最後申報的事實資料，且每個季度至少有一個概念於一年後再次申報。Frames 適用於橫斷面快照與原型開發。若面板必須回答某日期當時已知什麼，就必須從申報文件層級紀錄重建，讓每項事實資料保留最初申報它的文件之數值與日期。
4. 時點查詢依知悉時間篩選，依有效時間排名。依有效時間篩選，會納入尚未申報的季度，造成前瞻偏誤。依知悉時間排名，會傳回最近公布的列，而非最近季度，因此每次重編資料到來，都會在會計時間上倒退。上方比較計算某一日期兩種答案不同的公司數。
5. 知悉時間可能缺漏。沒有申報日的列永遠無法證明已公開，因此時點查詢會將其丟棄——若面板不說明有多少列如此，就會無聲發生。應回報此缺口，避免之後才發現無法解釋的涵蓋損失。
6. 下載器與載入器是正式運作介面。本 Notebook 用於檢查面板是否健全，並提供查詢範本；特徵工程則在 `08_financial_features/04_fundamentals_macro_calendar.py` 中進行。
