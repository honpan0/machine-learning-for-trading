沒有任何一列落在法定申報期限內。最短也超過一年，而大型申報者的 10-Q 須於季末後四十天內提交。

這不是申報延遲，而是 Frames API 傳回內容的特性。Frames 以報導該期間的*最新*申報文件中的形式傳回事實資料；此處每個季度至少有一個概念——通常是損益表——後來在一年後提交的比較資料中再次申報。該列包含此重編數值，因此直到比較資料申報後才全部公開，而以其最後一份申報文件定日，是唯一如實反映情況的方式。若改以最早申報日定日，就會將重編數值放在原始日期下發布，這正是本章圖 4.1 展示的前瞻問題。

這具體呈現了本章對 Frames 的論點：它為橫斷面快照與原型開發而建，本身無法確保歷史時點安全性。若面板必須回答「此日期當時已知什麼」，就必須從申報文件層級紀錄重建，讓每項事實資料保留最初申報該數值的文件之數值與日期。直方圖呈現這項代價的形狀：一個延後的群集，而非帶有尾部的法定期限分布。
