## 重點整理

1. 項目編號依表單類型而異。管理階層討論在 10-K 是 Item 7，在 10-Q 則是第一部分的 Item 2，因此為其中一種表單建立的擷取器，對另一種會無聲無息地回傳空結果。應依表單類型選擇模式集合，而非直接套用預設。
2. 項目標題會在申報中出現數次：在目錄、交叉參照，以及一次真正的章節標題。第一個匹配結果幾乎都不正確，而到下一個項目之間的跨度才是區分關鍵：目錄項目只有一行，章節則有數千行。
3. 清理過程中必須保留段落邊界。它們是變更偵測器比較的單位，而以空白串接區塊的轉換器會將它們不可逆地破壞。
4. 報告擷取率，而非只展示一個範例。失敗不會發出警訊：應是章節的位置，卻出現看似合理的短字串；在語料庫規模下，唯有計算空結果、過短結果，以及含有下一個項目標題的結果，才能抓到問題。
5. 以申報受理編號作為資料集鍵值，並保留受理時間戳記。存在修正申報時，公司與日期無法唯一識別一份申報；收盤後受理的申報，要到下一個交易時段才能據此交易。
6. 詞彙重疊與段落變更衡量的是不同事情。申報者可以重寫段落而不增加任何字詞，因此只依詞彙建立的訊號，恰好會漏掉重要的改寫。
