# 實體解析：將公司名稱配對至識別碼

**第四章：基本面與替代資料**
**Docker 映像檔**：`ml4t`
**章節參照**：第 4.2 節（實體解析與對應）

## 目的

凡是非價格行情的資料集，幾乎都以某人輸入的公司名稱作為索引鍵。職缺資料供應商寫的是「Microsoft Corporation - Redmond」；新聞來源寫的是「Microsoft Corp.」；SEC 寫的則是「MICROSOFT CORP」。要將其中任何一種資料與價格序列合併，就得判定這些名稱屬於同一家公司，而兩種方向的誤判代價都很高：漏配會丟棄該列，使樣本偏向名稱格式整齊的公司；誤配則將一家公司的資料接到另一家公司的報酬率上，產生披著公司名稱外衣、實則純屬雜訊的訊號。

本 Notebook 建立正式環境對應流程使用的三個階段，並以同一組已標註資料評估各階段，讓「每個階段處理前一階段無法處理的情況」成為可量測的結果，而非口號。

## 學習目標

完成本 Notebook 後，你將能夠：

- 列出證券主檔所連結的標準識別碼，並說明各自涵蓋的母體。
- 有識別碼時依識別碼合併兩個來源，沒有時則依明定的順序採用後備方法。
- 正規化公司名稱，讓法律組織型態後綴與標點符號不再主導字串比較。
- 以模糊字串指標評估名稱與參照清單的相似程度，並依量測的精確率與召回率選擇接受門檻，而非依靠經驗法則。
- 以句子嵌入評估同一批名稱，並顯示它能補救與無法補救的失敗情況。
- 解釋為何唯有經整理的別名表能解決更名或子公司問題，並建立這樣的表。
