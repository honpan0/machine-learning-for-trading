## 第 2 部分：讀取 XML

每份申報文件都有用於普通股的 `<nonDerivativeTable>`，以及用於選擇權和其他衍生工具的 `<derivativeTable>`，每張表中每筆交易各占一個交易區塊。這些區塊正是應使用 XML 解析器，而非對文件文字使用正規表示式的原因：正規表示式不知道區塊在哪裡結束，因此會將一筆交易的交易代碼與下一筆的價格配在一起，還會直接跨越普通股與選擇權的邊界。走訪樹狀結構可讓每個欄位固定屬於自己的交易。

### 本 Notebook 讀取的元素

| 元素 | 說明 |
|---------|-------------|
| `<issuerName>` | 股票被交易的公司 |
| `<reportingOwner>` | 每位申報內部人各有一個區塊 |
| `<rptOwnerName>` | 內部人姓名 |
| `<officerTitle>` | 內部人職位，若有任職 |
| `<nonDerivativeTransaction>` | 一筆普通股交易 |
| `<transactionCode>` | 交易類型 |
| `<transactionShares>` | 股數 |
| `<transactionPricePerShare>` | 每股價格，部分交易類型不提供 |
| `<transactionAcquiredDisposedCode>` | A 表示取得，D 表示處分 |

下方僅為計數而另行讀取衍生工具交易，讓本 Notebook 保留的列能與檔案中的全部內容核對。
