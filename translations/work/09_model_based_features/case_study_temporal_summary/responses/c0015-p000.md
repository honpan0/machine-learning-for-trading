## 重點整理

1. **讀取結構描述適合建立清單，卻不能用來提出成效主張。** 讀取九個 parquet 檔案尾端的中繼資料幾乎不費成本，也能知道有哪些欄位；但無法知道任何欄位有多少價值。這需要各案例研究模型階段的登錄資料比較結果。
2. **對欄位名稱進行子字串比對，是一項命名慣例檢查。** 它能找出按類別本義命名的特徵，卻會漏掉未如此命名的特徵。因此，表格中的零，可能表示某類別不存在，也可能表示名稱不同。名稱樣本可釐清個別情況；若持續擴充關鍵字清單，直到所有名稱都能匹配，等於取消檢查，而非通過檢查。
3. **覆蓋不均只說明建立了什麼、如何命名，不能說明什麼適合某個市場。** 某類別若未出現在市場的結構描述中，可能是不存在、名稱不同，或不在該案例研究範圍內；結構描述無法區分這三種情況。判斷某技術是否適合該市場，需要該案例研究自身的評估，而非這張表。
4. **產出檔缺席，只反映目前這份簽出版本的狀態。** 這些檔案由流程執行時產生，不會提交到儲存庫，因此空清單表示相關階段尚未執行。將它解讀成沒有特徵，正是這份 Notebook 要避免的誤讀。
