# 資料品質診斷

**Docker 映像檔**：`ml4t`

**第 7 章：定義學習任務**
**對應章節**：7.1——資料前處理與編碼

## 目的

本 Notebook 對所有 ML4T 資料集進行**標準化診斷調查**。不執行清理，只做評估。產出的是一份「健康報告」，指出哪些資料集需要主動前處理，哪些已處於良好狀態。

## 學習目標

1. 為金融追蹤資料建立可重複使用的診斷函式
2. 了解常見資料品質問題：缺漏、重複、離群值與資料間斷
3. 辨識影響機器學習流程設計的資料集特有情況
4. 建立系統化的資料驗證架構

## 書籍參照

第 7.1 節強調，**資料品質決定模型品質**。本 Notebook 在任何特徵工程之前，透過具體診斷落實這項原則。

## 先備條件

- 熟悉七個 ML4T 資料集及其載入器（`data` 模組）。
- 具備 Polars 基礎（`pl.DataFrame`、`group_by`、`with_columns`）。
- 不需要先前 Notebook 的輸出；本 Notebook 是流程的起點。

## 資料契約

- **輸入**：資料載入器提供的原始資料集（ETF、美國股票、加密資產等）
- **輸出**：診斷報告與品質評估（不修改資料）
