## 4. 定義含提前停止與剪枝的目標函數

Optuna 的 **define-by-run** API 可在目標函數內動態定義搜尋空間。我們加入兩項提高效率的機制：

- **提前停止**：LightGBM 監控驗證損失，當表現趨於平穩時便停止新增樹。因此，我們將 `n_estimators` 設得較高，讓回呼函數決定實際數量。
- **剪枝**：Optuna 的 `MedianPruner` 會終止在相同提升步驟下，驗證 IC 低於中位數的試驗。由於現成的 `optuna_integration.LightGBMPruningCallback` 只支援損失類型的指標（亦即最小化），我們改用簡短的自訂回呼函數，每 `report_every` 輪提升回報一次橫斷面 IC。
