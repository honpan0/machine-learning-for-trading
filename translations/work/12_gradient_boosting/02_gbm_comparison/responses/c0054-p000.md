## 13. 重點摘要

1. **這項單一折次基準測試無法對函式庫的準確度排序。**在 ETF 折次上，所有函式庫與預設組態的測試 IC 都是負值；上表列出其範圍。此基準測試旨在回答工程問題，包括時間、記憶體及裝置表現。準確度排序則需要以經調校的超參數進行多折交叉驗證；這正是 `04_optuna_tuning` 的內容。

2. **GPU 帶來多少效益取決於函式庫，原因在於架構。**LightGBM 的 CUDA 後端僅支援雙精度，而消費級 GPU 的 FP64 吞吐量僅為 FP32 的一小部分，因此它從 GPU 獲得的效益最少，在 CPU 上卻往往最快。表中的比值只代表這台機器此次執行的結果；可以推廣的是造成差異的原因。LightGBM 的 CUDA 路徑還必須使用 `ml4t-gpu` 映像檔：本機虛擬環境中的 PyPI wheel 並未包含 CUDA 建置版本。

3. **CPU 與 GPU 是相關但不同的估計器。**不同精度的直方圖分箱會改變切分點，這些差異會在集成模型中逐步累積，造成超出四捨五入程度的 IC 差異。不能把 GPU 重新執行視為重現 CPU 結果。

4. **記憶體圖面顯示的是下界，而且大多數數值為零。**RSS 差值主要受記憶體配置器與垃圾回收時機影響，也無法觀測原生程式碼或裝置上的記憶體配置，因此既不能用來排列函式庫，也不能據以決定硬體規格。這些用途應使用分析工具或尖峰 RSS；此圖面旨在顯示簡易探測能與不能捕捉的資訊。
