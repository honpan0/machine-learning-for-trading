# 檔案格式儲存效能評測

**環境**：鎖定的環境（`uv run`），請見下方先備條件。

**目的**：以同一份 100 萬列 OHLCV 追蹤資料，從三個面向比較 CSV、Parquet、Feather（Arrow IPC）與 HDF5：寫入時間、讀取時間（強制實體化）及磁碟空間大小，讓 §2.4 的取捨能以端到端方式重現。

**學習目標**：
1. 以第 §2.4 節引用的 L 規模，產生結果確定的 OHLCV 效能評測追蹤資料（100 個代號 × 10,000 根一分鐘 K 棒 = 1,000,000 列）。
2. 依同一套明訂的計時規則，量測每種格式的寫入與讀取時間。
3. 在讀取 Feather／HDF5 時強制實體化，避免將記憶體映射或延遲讀取誤認為瞬間完成。
4. 量化欄位投影的效益（讀取 2 欄與 9 欄相比）。
5. 繪製三面板比較圖（讀取時間／寫入時間／檔案大小）。

**書籍參照**：§2.4——以檔案為基礎的儲存效能評測。

**先備條件**：PyTables（HDF5 後端）隨附於鎖定的環境，因此只要從儲存庫根目錄執行 `uv run python 02_financial_data_universe/20_storage_benchmark_file.py`，就具備本 Notebook 所需的環境；與 `21_storage_benchmark_database` 不同，無需資料庫服務。

> **產生這些數據的環境**：鎖定的環境（`uv sync`，即 `uv.lock`），也是 §2.4 報告所用的環境。`benchmark` Docker 映像目前解析出的 pandas 版本，比 `uv.lock` 固定的版本*更新*；較新 pandas 的字串資料型別，會讓 PyTables 儲存低基數的 `symbol` 欄位時，每列多占約 8 位元組，足以讓相同追蹤資料的 HDF5 檔案從約 71 MB 增至約 79 MB。CSV、Parquet 與 Feather 不受影響。請在 `uv run` 下執行本 Notebook，以重現 §2.4。
