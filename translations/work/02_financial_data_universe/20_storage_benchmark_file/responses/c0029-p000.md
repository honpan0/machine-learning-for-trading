## 重點整理

- **記憶體映射不等於讀取。** 單純取得 Feather 控制代碼幾乎立刻就會傳回，因為尚未存取任何內容；成本在首次存取頁面時才會出現。實體化讀取才是讓四種格式站在相同基準上的比較，也是上圖繪製的數值。
- **沒有任何格式能在三個面板全部勝出。** 讀取最快、寫入最快及磁碟占用最小的，並非同一種格式，因此選擇是一種取捨，而非單純排名。哪個面向構成限制，取決於追蹤資料是寫入一次後持續讀取，還是需要跨網路傳輸。
- **欄位投影讓欄式格式變快，而 CSV 無法具備這項能力。** 對 Parquet 與 Feather 而言，讀取少數幾欄而非整個結構描述的所有欄位，成本大致與所請求的欄位成正比。CSV 幾乎無法受益，因為要存取一列中較後面的欄位，就必須解析前面的每個欄位。
- **壓縮縮小的是檔案，而非資料框。** Parquet 寫入的追蹤資料大小僅為 CSV 的一部分，但讀回後的記憶體占用完全相同，因為兩者最終都存入相同的 Arrow 緩衝區。格式選擇決定的是磁碟與網路成本，不會改變資料載入後的占用成本。
- **HDF5 fixed 格式採整份讀寫。** 它可以讀取或寫入整份追蹤資料，但不提供欄位投影。

### 格式選擇

- **長期儲存、雲端、跨語言**：Parquet。
- **Python 工具之間的本機交換**：Feather。
- **需要附加寫入的傳統科學運算 Python 流程**：HDF5。
- **人工檢視或小量匯出**：CSV。
