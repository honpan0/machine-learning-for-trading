## 大小欄位代表什麼，以及不代表什麼

與計時不同，各引擎的磁碟空間大小**並非**以相同方式量測，因為每個引擎只提供自己的統計方式。大小欄位應解讀為「此引擎回報自身使用的空間」，不能視為同等條件下的壓縮率：

| 引擎 | 回報來源 | 計入內容 |
|--------|-------------|--------|
| SQLite／DuckDB | 磁碟上的檔案大小 | 資料庫檔案 |
| ClickHouse | `system.parts.bytes_on_disk` | **壓縮後**的資料分片 |
| QuestDB | `table_storage().diskSize` | 資料表在磁碟上的完整占用空間 |
| PostgreSQL／TimescaleDB | `pg_total_relation_size`／`hypertable_size` | 資料表**加上索引**（若為超級資料表，亦包含其所有區塊） |
| InfluxDB | *未提供* | 用戶端 API 不回報各 bucket 的大小，因此留空，而非記為零 |

將 ClickHouse 的壓縮資料分片，與 PostgreSQL 的資料表加索引總量相比，並非壓縮率比較。檔案格式 Notebook（`20_storage_benchmark_file`）才是以相同方式量測各比較對象大小、可直接比較之處。

## 快速開始

```bash
# Embedded engines only. DuckDB and SQLite need nothing beyond the base install.
uv run python 02_financial_data_universe/21_storage_benchmark_database.py

# With the server engines as well, from the host (compose publishes their ports)
docker compose --profile databases up -d timescaledb postgres clickhouse questdb influxdb
uv run --extra db-benchmark python 02_financial_data_universe/21_storage_benchmark_database.py
```
