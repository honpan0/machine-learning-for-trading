### TimescaleDB 寫入

`execute_values` 接收 Python 元組序列，因此在任何資料抵達伺服器之前，必須先將追蹤資料轉成每列一個元組。建構時使用 `itertuples`，而非 `iterrows`：`iterrows` 會先將每列包裝成 Series，再產生比較結果相等的元組，成本卻高出一個數量級。差異來自 pandas，而非資料庫，先前卻被計入此引擎的寫入長條。下方儲存格會印出本次執行的建構成本。

大小方面，使用 `hypertable_size()` 而非 `pg_total_relation_size()`：超級資料表的資料列存放在子區塊中，因此父關聯是空的，`pg_total_relation_size` 回報的約 16 kB 是系統目錄額外負擔，而非資料。
