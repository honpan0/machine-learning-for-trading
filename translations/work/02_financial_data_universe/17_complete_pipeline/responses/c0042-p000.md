## 重點整理

1. **拼接面對的是兩套調整基準，而非兩個日期範圍。** 在接合點篩選各來源再串接，只要較舊來源停止後發生了公司行動，就會留下階梯落差，因為較舊來源無法針對從未見過的事件進行追溯調整。兩段資料都已調整股利，因此接合處的一個比值即可消除差異，而成交量則使用同一因子的倒數。

2. **為每列標記來源。** `source` 欄位讓上圖中的接合點清楚可見、讓供應商不一致問題可供除錯，也讓資料遷移可逆。代價只是一個欄位。

3. **驗證器必須符合所驗證資料的時間頻率。** 股票流程將多日缺漏視為異常，加密貨幣流程則將超過一根 K 棒的缺漏視為異常，因為股票市場會休市，永續期貨市場則不會。將任一門檻用在另一份追蹤資料上，就會把交易日曆當成故障，或漏掉所有服務中斷。

4. **股票驗證器找到的缺漏來自交易日曆，但它無法告訴你這一點。** 各代號標記出的缺漏都是同一次市場休市，這是關於 2001 年 9 月的事實，而非資料供應的問題。缺漏偵測器能找出不連續處；判定原因則需要交易日曆。

5. **當流程不再變動時，改用 `DataManager`。** 上方明確列出的類別，是為了展示高階 API 正在做什麼。第 5 節透過該 API 重現相同工作，而正式環境採用的是較精簡的做法。
