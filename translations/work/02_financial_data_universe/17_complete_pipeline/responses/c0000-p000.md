# 完整資料流程：從多來源擷取到可供機器學習使用的資料

**Docker 映像**：`ml4t`

## 目的
將本章的各個元件——多供應商擷取、OHLC 驗證、來源標記及高效率儲存——串成兩個端到端流程：股票流程拼接 WikiPrices（1990–2018）與 Yahoo（2018 年至今），加密貨幣流程則使用本機 Binance 每小時永續期貨追蹤資料。接著，本 Notebook 示範 `ml4t.data.DataManager` 如何以少得多的程式碼完成相同工作。

## 學習目標
- 建立多來源股票資料流程，並在每個邊界執行驗證。
- 偵測全天候資料涵蓋範圍的缺漏，並為加密貨幣資料加入交易時段特徵。
- 為每一列標記來源，讓多來源資料可供稽核。
- 以 `DataManager` + `Universe` + `HiveStorage` 高階 API 取代明確列出各步驟的流程，這些 API 隨附於 `ml4t.data`。

## 書籍參照
第 2 章，§2.3（多來源資料拼接與正式環境流程）。流程輸出供 ETF 與加密貨幣永續期貨案例研究使用。

## 先備條件
- 位於 `ML4T_DATA_PATH/equities/market/us_equities/us_equities.parquet` 的 WikiPrices parquet。
- 可透過 `data.load_crypto_perps` 載入的加密貨幣永續期貨每小時 parquet。
- 可即時存取 YahooFinance（股票流程會呼叫它來取得 2018 年至今的資料，慣例與 `16_provider_comparison` 相同）。

## 標的池選擇說明
WikiPrices 涵蓋美國個股（約 3,200 個股票代號，1962–2018），但**不包含**指數 ETF。下方股票流程的示範標的池使用三檔大型股（AAPL、MSFT、JPM），讓 WikiPrices 與 Yahoo 的拼接具有實質意義；ETF 輪動案例研究本身則只使用 Yahoo 自 2008 年起的資料（見 `case_studies/etfs/`）。
