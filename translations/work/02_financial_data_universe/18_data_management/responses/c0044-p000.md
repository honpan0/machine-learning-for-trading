## 摘要

| 元件 | 用途 | 主要方法 |
|-----------|---------|------------|
| **DataManager** | 統一入口 | `fetch()`、`batch_load()`、`load()`、`update()` |
| **Universe** | 預先定義的代號清單 | `Universe.SP500`、`Universe.get("nasdaq100")` |
| **HiveStorage** | 分割區 Parquet | `read()`、`write()`、分割區裁剪 |
| **GapDetector** | 時間序列缺漏偵測 | `detect_gaps()`、`detect_gaps_in_storage()` |
| **CLI** | 指令碼工作流程與 cron | `ml4t-data fetch`、`ml4t-data update` |

### ml4t-data 工作流程

```
1. Initial load:    dm.load("AAPL", "2020-01-01", "2024-12-31")
2. Daily update:    dm.update("AAPL", lookback_days=7)
3. Gap check:       gap_detector.detect_gaps(df, frequency="daily")
4. Batch load:      dm.batch_load_universe("sp500", start, end)
5. Automate:        cron + ml4t-data update --all
```

### 重點整理

- **單一入口，多個供應商。** `DataManager.fetch()` 隱藏資料位元組究竟來自 Yahoo、Binance、AlgoSeek 或本機 Hive parquet；供應商變更時，使用者程式碼無需改動。
- **`load()` 優先使用快取，`fetch()` 優先使用供應商。** 研究／回測使用 `load()`（快速、離線、結果確定）；只有必須重新整理快取時才使用 `fetch()`。
- **標的池是一等公民。** `Universe.SP500` 等功能讓代號清單不必寫在 Notebook 程式碼中，而是在函式庫內進行版本控制。
- **缺漏偵測是獨立的工作。** `GapDetector` 針對已儲存資料執行；缺少的交易日會以檢查發現呈現，不會默默成為空值。
- **CLI 是正式環境的操作介面。** 由 cron 驅動的 `ml4t-data update --all`，與 Notebook 使用相同的程式碼執行路徑。
