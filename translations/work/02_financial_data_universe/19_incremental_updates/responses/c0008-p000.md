### 步驟 2：增量更新（僅新資料）

更新會讀取儲存空間中的最後時間戳記，重新擷取一小段重疊資料（`UPDATE_LOOKBACK_DAYS`），讓供應商修訂的 K 棒取代已儲存的版本，並合併自該處起的所有資料。

**在哪裡結束，比從哪裡開始更重要。** Yahoo 會將交易所當日資料傳回為一列，其中成交量持續累積，卻沒有開盤／最高／最低／收盤價。沒有價格的 K 棒不算 K 棒，供應商也會明確指出：

```
DataValidationError: yahoo: Column 'open' contains 1 null values
```

`DataManager.update()` 擷取至 `datetime.now()`，因此每個交易日都會請求該列並引發錯誤。`update_through_last_complete_bar` 執行相同的增量更新，但會**尋找**視窗終點，而非計算一個終點。它從交易所當日前一天開始——採交易所時間而非 UTC，因為紐約時間 22:00 時，UTC 日期已經是明天——只要供應商拒絕該視窗，就逐日向前回退。

回退能做到單憑日期做不到的事。佔位列通常會在收盤後幾小時內補齊，但有時並不會：Yahoo 的 AAPL 2026-09-03 日 K 棒，在八個半小時後仍是 `NaN, NaN, NaN, NaN, 37197362`，而同一視窗若結束於 2026-09-02，每個欄位都正常。從日曆看來，兩者完全一樣，因此必須實際詢問供應商。

當視窗遭拒時，ml4t-data 會以錯誤等級記錄。如果你在下方看到 `Failed to fetch AAPL: yahoo: Column 'open' contains 1 null values`，下一行卻接著出現資料列數，表示回退機制正在運作：第一個視窗請求了供應商尚未發布的 K 棒，第二個視窗則成功取得資料。
