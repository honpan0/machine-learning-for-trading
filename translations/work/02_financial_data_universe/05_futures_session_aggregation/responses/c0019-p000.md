## 3b. 比率反向調整

Databento 的連續合約資料未經調整，因此每次轉倉時價格都會出現跳躍，而跨越該跳躍計算出的報酬率，反映的是兩份合約之間的價差，而非市場價格的變動。

下方的轉倉表列出這些價格跳躍的幅度。我們使用 `instrument_id` 偵測轉倉點，並套用\*\*比率（乘法）\*\*反向調整：

1. 偵測同一序列中相鄰資料列的 `instrument_id` 何時發生變化。
2. 計算比率 = 新合約收盤價 / 舊合約收盤價，且兩者必須取自相同小時。
3. 從後往前累積比率（最近期的價格維持不調整）。
4. 將所有 OHLC 價格乘上累積比率。

步驟 2 是最容易出錯的地方。相鄰的資料列不代表相鄰的小時：ES 近月合約可能從週五上午舊合約的最後一筆價格資料，轉倉至 57 小時後週日晚間新合約的開盤資料。如果使用新合約開盤價除以舊合約收盤價，就會拿兩個不同日期的價格相除，使調整因子吸收週末期間的市場變動，導致調整後的序列在持有者實際獲得報酬的地方，卻顯示沒有報酬。

在舊合約最後一小時，通常可以從下一個到期期別取得即將轉入合約的報價，而 `data.futures.roll` 會從該處取得這組配對價格；如果無法取得，則退而使用新合約第一小時的價格。如果這兩個小時都無法同時取得兩份合約的報價，就會標記該次轉倉，而不是在未說明的情況下混用不同時間的價格。

比率調整能保留百分比報酬率（這對 IC、動能特徵及回測至關重要）；相較之下，Panama（加法）調整會扭曲較早期資料的報酬率，對於累積調整幅度較大的商品，甚至可能使價格變成負值。

關於調整方法的教學說明，請參閱 `06_futures_continuous`。
