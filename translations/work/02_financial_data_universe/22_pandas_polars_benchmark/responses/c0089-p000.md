## 類別 G：記憶體使用效率

本節只回報各函式庫自行計算的資料框記憶體占用，不涵蓋其他項目。

過去會在單次複製前後讀取 `psutil` 常駐集大小，將差值回報為該副本的記憶體用量。常駐集差值無法回答這個問題：配置器會從已持有的頁面滿足配置要求，釋放時也不將記憶體歸還核心，因此讀值隨配置器狀態變動，而非反映副本用量；印出的兩個數字也沒有供 Notebook 的其他部分使用。

只要說明兩種計算方式的差異，其實際量測內容就值得了解。兩邊的數值欄位，每個值都是八個位元組，對用量比率幾乎沒有貢獻。差異全在代號欄位，而兩個函式庫的表示方式不同：pandas 將物件欄位儲存為指向 Python 字串物件的指標陣列，每個物件又帶有自己的標頭，因此七個字元的股票代號會占用數十個位元組。Polars 將同一欄位儲存為緊密排列的 UTF-8 資料與偏移量，代號的成本大致就是其字元所需空間。

這裡兩邊都未針對重複值採取特殊處理。欄位是 `pl.String`，並維持該型別：不同代號只有少數幾個，轉為類別型別可進一步縮小欄位，但那是另一種量測，本 Notebook 並未執行。

下方兩個數值都以位元組讀取，再除以相同因子。Polars 的 `estimated_size("mb")` 傳回二進位百萬位元組，pandas 的 `memory_usage` 則傳回位元組，因此若將其中一個除以 1e6，另一個直接使用，就會讓比率膨脹約百分之五；差異小到看起來像兩個函式庫之間的真實差異。
