兩個共用輔助函式負責各處都必須一致的處理。`filtered_state_probs` 執行向前遞迴，產生 $P(z_t \mid x_{1:t})$，而非函式庫預設傳回的平滑後驗機率；`sort_states_by_variance` 則依離散程度排列狀態，確保每次重新擬合時，狀態 0 的含義一致。採用重新擬合時程後，第二個函式比採用切分時更重要，而非較不重要：期望最大化法會任意替狀態編號，若無固定順序，這項特徵在整段歷史中可能數百次交換含義，而非只有兩次。它們放在 `case_studies/utils/temporal.py` 中，因為只有每份 Notebook 都以相同方式排序狀態，市場狀態特徵才能跨估計結果比較；向前遞迴也會呼叫建模函式庫的私有方法，應集中於單一位置，而非散落各處。

第三個函式是 `fit_hmm_restarts`，負責搜尋。期望最大化法可能收斂至局部最適解，因此本 Notebook 一直在每次重新擬合時，從十個起點擬合，保留訓練資料概似值最高的結果。該迴圈過去寫在此處；現在移至共用模組，因為 `etfs` 與 `fx_pairs` 也各自寫了一份相同迴圈，三份選擇規則就有三處可能產生歧異。

底層改變的是重新啟動的起點。現在擬合會由訓練視窗的 k-means 分群初始化，而非使用建模函式庫自身的方法；這個起點由資料而非隨機種子決定。多次起始擬合仍保留：在 `etfs` 的面板上，用同一估計器測量，十次起始擬合得到十個不同的對數概似值，因此較佳起點並未使搜尋變得多餘。
