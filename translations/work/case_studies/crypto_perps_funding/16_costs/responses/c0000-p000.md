# 加密貨幣永續合約：最終入選配置能承受多少交易摩擦

至今每次回測都採用同一套成本設定，也就是 `config/setup.yaml` 所宣告的設定。本 Notebook 將通過整個篩選流程的配置完全固定，包括相同模型、相同檢查點、相同進場規則、相同資金配置器及相同風險控制，只改變交易成本。

**此階段不進行任何選擇。** 其前後三個階段逐步縮小候選範圍：基準階段執行所有配置，資金配置階段執行排名前十的配置，風險覆蓋階段執行排名第一的配置。成本敏感度分析也執行排名第一的配置，但它並非在候選者之間做選擇，而是針對已選定的配置提出問題；答案是一條曲線，而非排名。後續流程不會讀取此處的排名。

以曲線作為輸出，是因為單一成本假設終究只是猜測。宣告的成本設定只是曲線上的一點；若結果只在該點成立，反映的就是這項猜測，而非策略本身。曲線顯示成本假設可以變動多遠，才會改變結論。

**學習目標。** 完成本 Notebook 後，你將能夠：

- 將以基點表示的成本水準解讀為對交易名目金額收取的費用，並說明為何是週轉率而非費率，將其轉化為夏普比率的變化。
- 區分隨費率變動的逐筆交易執行費用，以及取決於持有部位、因此不隨費率變動的資金費現金流。
- 從成本衰減曲線讀取損益兩平點，而非只看單一估計值。
- 說明為何均一成本網格是敏感度分析軸，而非宣告費用結構的忠實重現。
