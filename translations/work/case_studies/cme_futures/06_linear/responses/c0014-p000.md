第二次執行時，`reused` 不會是零。每個身分都由輸入重新推導，登錄表已保存相符資料列，執行器直接傳回既存結果，而不再擬合；因此不變更內容就重跑此 Notebook，只需花讀取資料的時間。

### 執行自訂設定

已發布的執行紀錄是唯讀的。若要新增執行結果，應以工作區開啟研究；工作區有自己的登錄表與產出檔案，但讀取相同標籤與特徵：

```python
study = open_study("cme_futures", workspace="~/ml4t-experiments")
configs = load_model_configs(
    study, "linear", labels=["fwd_ret_5d"], config_names=["ols", "ridge_a1.0", "ridge_a3.0"]
)
requests = model_requests(study, configs)
resolved = tuple(request.resolve() for request in requests)
execution, population = run_model_population(study, resolved, population_name="my-linear-v1")
```

`CONFIG_NAMES` 會擬合選單已宣告設定的子集；若指定選單未宣告的名稱，系統會報錯，而非默默擬合比要求更少的模型。若要擬合新設定，在 `case_studies/config/ridge/ridge_a3.0.yaml` 新增預設檔，並將 `ridge_a3.0` 列於該標籤選單的 `linear:` 下。編輯既有預設檔會改變設定身分，因此結果會登錄為舊列旁邊的新列，而非取代舊列。
