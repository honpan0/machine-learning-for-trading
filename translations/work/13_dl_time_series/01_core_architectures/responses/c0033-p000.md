### 計算單一步驟的訓練時間

總訓練時間不適合衡量架構成本。同一張 GPU 上執行的其他工作會拉長時間，而且在 `BATCH_SIZE` 為 32 時，每個訓練週期有很大一部分時間花在 Python 啟動工作，而非實際運算；這對不同架構造成不等程度的美化或不利影響。

因此改為測量固定批次 `BENCH_BATCH` 個視窗的一個訓練步驟，也就是一次前向傳遞、一次反向傳遞和一次權重更新。前 `warmup` 個步驟會捨棄，因為首次呼叫 GPU 核心時會付出記憶體配置和核心編譯成本，後續呼叫不會重複。接著執行該步驟 `repeats` 次，報告其中**最快**的一次。刻意取最小值而非平均值，是因為步驟的真正成本是一個下限；任何使測量值高於下限的因素，例如排程器搶占或其他程序，都只會增加時間。在 GPU 上，計時使用 CUDA 事件而非牆上時鐘，因為 GPU 呼叫會在工作完成前就返回 Python，牆上時鐘測到的會是排隊時間，而非算術運算時間。

結果仍取決於機器。應觀察架構之間的快慢順序，以及這個順序如何隨視窗長度改變；不要將毫秒數視為架構本身的固有屬性。
