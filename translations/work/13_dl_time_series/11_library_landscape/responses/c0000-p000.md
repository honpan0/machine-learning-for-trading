# 以六種方式撰寫相同的預測

**Docker 映像檔**：`ml4t-gpu`

本章至今的每份 Notebook 都直接使用 PyTorch 撰寫：模型類別、訓練迴圈及評估區塊。這是學習架構的好方法，卻不是嘗試五種架構的有效方式。本 Notebook 透過數個程式庫撰寫相同的單變量預測，並比較*使用體驗*：需要多少行程式、必須安裝什麼，以及介面帶來哪些限制。

最值得理解的是 **sktime**，因為它並非模型程式庫，而是一套介面：`fit`、`predict`、`update`。它將工作交給 NeuralForecast、PyTorch Forecasting、HuggingFace 與傳統方法，因此將 LSTM 換成 Chronos 或 ARIMA，只需更換建構函式，無需重寫程式。**Darts** 則採用另一種方式：它有自己的 `TimeSeries` 容器及模型實作。

**表格衡量的是工作量，不是準確度。** 各列沒有共用目標尺度或測試集，因此無法跨列比較誤差欄；這一點會在表格出現處說明，也會在表格欄位標示。加入最近值基準模型，正是為了讓唯一*條件相同*的比較也呈現在頁面上。

**學習目標**：
- 分別使用原始框架與封裝介面撰寫相同的預測，並計算封裝介面實際省下多少工作。
- 閱讀比較表，辨識哪些欄位可跨列比較，哪些不行。
- 說明目標是價格水準而非報酬率時，等級相關係數代表什麼。
- 判斷介面限制是否值得以減少重複程式碼作為交換。
