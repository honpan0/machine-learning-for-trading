## 何時使用各種方法

正文第 13.7 節比較程式庫的*功能*（例如面板支援、基礎模型）。此表聚焦於*實作體驗*：

| 方法 | 實作工作量 | 彈性 | 適用情境 |
|----------|----------------------|-------------|----------|
| **原始 PyTorch** | 約 50 行，需完整制式程式碼 | 可全面掌控 | 自訂架構、橫斷面排序、研究 |
| **sktime** | 約 3 至 8 行 | 受 `fit`/`predict` API 限制 | 快速製作原型、更換後端、標準化基準測試 |
| **Darts** | 約 10 行 | 中等（使用自己的 `TimeSeries` 容器） | 機率預測、自成一體的生態系 |
| **Chronos／時間序列基礎模型** | 約 3 行，無需訓練 | 無（僅零樣本模式） | 即時基準模型、冷啟動情境 |

sktime 不是模型程式庫，而是單一介面：`fit`、`predict`、`update`。它將工作交給 NeuralForecast（LSTM、TCN）、PyTorch Forecasting（N-BEATS、TFT）、HuggingFace（PatchTST、Chronos）與傳統方法（ETS、ARIMA），因此不需修改資料流程，就能對 LSTM、基礎模型與 ARIMA 進行基準測試。本 Notebook 也顯示這層間接介面的代價：其中兩個後端無法在此安裝或呼叫，若後端本身不存在，介面也無濟於事。
