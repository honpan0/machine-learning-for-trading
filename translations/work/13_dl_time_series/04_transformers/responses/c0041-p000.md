## 重點整理

1. **token 的定義決定注意力機制能做什麼。** 自注意力機制建立 token 之間的關係，除了 token 自身承載的資訊，沒有其他順序概念。因此，一天一個 token 的一般做法，給它的是 60 個可互換的純量。分片將局部形狀放進 token；倒置則將完整變數放進 token。兩種架構都是這項決策的結果，而非更大的模型。
2. **分片使注意力成本隨片段大小以平方幅度下降。** 注意力成本隨 token 數量按 $O(L^2)$ 成長，因此若每個 token 涵蓋 `PATCH_SIZE` 天，而視窗長 $L$ 天，成本就成為 $O((L/P)^2)$；這使長視窗的成本可負擔，也是縮短視窗之前應先考慮分片的原因。
3. **倒置設計不需要位置編碼，這是設計結果而非單純節省成本。** 其 token 是特徵，而特徵沒有要編碼的自然順序；時間順序存在於 token 內部，由投影處理。要問架構如何處理位置，應先問它的 token 是什麼。
4. **分別閱讀各注意力頭的矩陣，並將其視為描述。** PyTorch 預設會跨注意力頭取平均，而平均結果不代表任何單一注意力頭的行為。即使分別觀察各頭，注意力權重仍不等於重要性，因為殘差路徑可繞過注意力區塊；這些矩陣說明的是一次內部運算做了什麼，而非哪些輸入真正重要。
5. **分別評分排序與校準，兩者都要與 Transformer 以外的模型比較。** 在相同攤平視窗上執行的嶺迴歸，才能判斷架構是否帶來價值；只比較兩種 Transformer 無法回答這個問題。
