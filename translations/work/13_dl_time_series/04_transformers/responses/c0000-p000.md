# 時間序列的 Transformer 架構

**Docker 映像檔**：`ml4t-gpu`

`03_great_debate` 測得：打亂每段輸入視窗內的日期後，某個 Transformer 的預測幾乎不變，線性模型的預測變動幅度卻超過它們自身的大小；在該測試集上，Transformer 並未使用時間順序。注意力機制比較每個 token 與其他所有 token，本身沒有內建的順序概念，因此 token *是什麼*，決定了注意力機制能找到什麼。一般設計以一天為一個 token，讓注意力機制面對 60 個幾乎可互換的純量並試圖找出關係。

此處兩種架構都透過改變 token 回應這個問題。**PatchTST** 以連續幾天的短片段作為一個 token，因此每個 token 承載一小段局部形狀，而非單一數值。**iTransformer** 更進一步，以某個特徵的完整歷史作為 token，因此注意力機制比較的是完整變數，時間順序則存在於 token 內部，而非 token 之間。兩者都不是更大的 Transformer；它們對應比較什麼與什麼，給出不同答案。

**學習目標**：
- 一次針對一個特徵建立分片 Transformer，並說明視窗變長時，分片如何降低注意力計算成本。
- 建立以特徵為 token 的倒置 Transformer，解釋一般設計需要位置編碼，它卻為何不需要。
- 在相同的攤平視窗上，將兩者與嶺迴歸及預測零比較評分，讓架構之間的差異能對照它們與無訊號預測的差距。
- 讀取各注意力頭的矩陣，說明這種矩陣對哪些輸入重要能證明什麼、不能證明什麼。

**書籍參考**：第 13 章第 13.5 節（現代 Transformer 變體）。PatchTST：Nie 等人（2023）；iTransformer：Liu 等人（2024）。
